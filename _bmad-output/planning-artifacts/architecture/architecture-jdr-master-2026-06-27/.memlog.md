# Architecture Memlog — Palier 2 Calendrier

- event: spine initiée, fast path, brownfield (Palier 1 auth+parties+invitations en place)
- constraint: paradigme NestJS modular (controller → service → PrismaService global) — hérité du Palier 1, read-only
- constraint: Angular standalone components + Signals pour l'état réactif — hérité du Palier 1
- constraint: auth session-based (express-session + AuthenticatedGuard) — toutes les routes protégées, hérité
- constraint: PrismaService est global (GlobalModule) — aucun module ne le réimporte
- constraint: PartiesModule exporte PartiesService pour les modules qui en ont besoin (pattern établi par InvitationsModule)
- decision: AvailabilityModule créé dans apps/api/src/availability/ — owns AvailabilityDeclaration, computeSlotStatus. Scope USER (déclarations globales, pas par partie). Exporte AvailabilityService.
- decision: PollModule créé dans apps/api/src/poll/ — owns SessionPoll, PollOption, PollVote. Scope PARTIE. Importe PartiesModule (vérif mjId). Importe AvailabilityModule (calcul créneaux pour le vote).
- decision: GET /parties/:id/available-slots vit dans PartiesController (sub-resource naturelle). PartiesModule importe AvailabilityModule pour y accéder. PollModule importe aussi AvailabilityModule.
- decision: computeSlotStatus(userId, date, slot) vit exclusivement dans AvailabilityService. Jamais dans un controller ni dans PollService — règle de propriété des données.
- decision: "un seul OPEN poll par partie" enforced dans PollService avant création (pas en DB constraint unique partielle, car Prisma 7 ne le supporte pas nativement). @@index([partieId, status]) aide la requête de vérification.
- decision: Frontend — AvailabilityService dans core/availability/, PollService dans core/poll/, ThemeToneService dans core/theme/. Suit le pattern core/ existant.
- decision: Frontend — CalendarFeature dans features/calendar/ avec deux composants principaux: CalendarViewComponent (conteneur mois/semaine) + ConstraintPanelComponent (bottom-sheet mobile / side-panel desktop).
- decision: ThemeToneService expose deux signals : activeTheme (CSS class sur body) et tone (Record<string, string> de microcopy). Changer le thème change les deux simultanément.
- decision: Routes Angular ajoutées : /profile/calendar (déclarations perso, joueur + MJ) et /parties/:id/calendar (vue MJ "Trouver une date" avec split layout).
- decision: Shared types — DaySlot, AvailKind, RecurKind, PollStatus, VoteAnswer, SlotStatus + DTOs (AvailabilityDeclarationDto, CreateAvailabilityDto, SessionPollDto, PollVoteDto, AvailableSlotDto) ajoutés dans packages/shared/
- assumption: [ASSUMPTION] La migration Prisma pour les 5 nouveaux modèles (AvailabilityDeclaration, SessionPoll, PollOption, PollVote + 5 enums) est créée via `prisma migrate dev --name calendar_p2`
- assumption: [ASSUMPTION] L'algorithme computeSlotStatus opère en mémoire sur les déclarations chargées (pas de requête SQL par slot). Performance NFR-2 (<1s pour 6 membres × 8 semaines) atteignable car ~6×8×3=144 slots max, calcul O(n×d) où n=déclarations actives par user.
- event: spine finalisée

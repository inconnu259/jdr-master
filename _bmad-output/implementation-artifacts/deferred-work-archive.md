son refetch existant. Cf. `docs/backlog.md` Palier 7 pour le détail.

## Décision à prendre : suppression d'un compte MJ (hors Epic 2)

Contexte : si un compte utilisateur est supprimé alors qu'il est MJ d'une ou plusieurs parties, celles-ci se retrouvent dans un état "zombie" (`partie.mjId` pointe vers un user inexistant). Deux stratégies possibles :

**Option A — Cascade delete** : supprimer le user supprime automatiquement toutes ses parties (ON DELETE CASCADE sur `partie.mjId`). Simple, propre, mais destructif pour les joueurs.

**Option B — Disable party** : supprimer le user désactive ses parties (champ `status: 'DISABLED'` à ajouter au schema). Les joueurs peuvent toujours consulter les notes, l'historique, etc., mais impossible de planifier des événements, d'ajouter des membres, ou de continuer à travailler avec la partie.

→ Décision utilisateur : option B préférée (conserver l'historique pour les joueurs). À implémenter lors d'un epic "Gestion des comptes / suppression de compte".

- (decision) Scope = P3 du brainstorm roadmap (moteur plugin GameSystem + premier système jouable), correspond au 'Palier 2' de docs/backlog.md dans le vocabulaire de l'utilisateur. Draconis reporté.
- (decision) Premier système = Ryuutama (pas Draconis), conforme à l'ordre déjà décidé dans le brainstorm du 26/06 (Ryuutama -> Conte de Minuit -> Draconis, stratégie risque minimal).
- (decision) Source des règles de création de personnage = PDF 'Guide du Voyageur' fourni par l'utilisateur (46 pages), extrait intégralement par sous-agent -> versé en addendum.md.
- (decision) Autres PDFs Ryuutama (personnage du MJ/homme-dragon, catalogue équipement complet, notes, villes) explicitement hors scope de ce palier, à ajouter dans un palier ultérieur une fois la création de base fonctionnelle.
- (decision) Type 'Magie' inclus comme type sélectionnable (avantages passifs : +4 PE, accès Grimoire/Saisons) mais le choix de sorts et la mécanique de lancer (8 pages du guide) sont différés à un futur palier -- à notifier clairement au joueur dans l'UI.
- (decision) Étape équipement = option 'pique-nique' simplifiée uniquement (équipement fixe, pas de budget/catalogue à gérer). Achat complet avec 1000 Po et catalogue d'objets reporté.
- (decision) Enjeu = usage perso/interne (scope-1), comme le PRD Calendrier précédent -- PRD court, pas de section marché/investisseurs.
- (decision) Rôle de groupe (cartographe/chef/chroniqueur/intendant) hors scope de la création de personnage -- décidé en session de jeu 1, pas à la création. Noté comme futur champ à ajouter sur la fiche plus tard.
- (decision) Seed JSON Ryuutama basé directement sur l'extraction PDF (addendum.md). Stocké dans un dossier data/ (ou équivalent) explicitement gitignoré -- contenu sous droits (Ryuutama est un système commercial, cf. docs/spec.md). Chaque instance doit fournir son propre seed localement.
- (decision) validate() = blocage dur (pass/fail), pas de mécanisme de dérogation construit dans ce palier. L'override MJ (niveaux 2-3) reste explicitement du ressort de P4 ; validate() reste une fonction séparée/composable pour ne pas devoir réécrire l'interface plus tard.
- (decision) Export PDF = remplissage de la fiche officielle vierge Ryuutama (pages 43-46 du guide) -- PDFs des fiches vierges à fournir ultérieurement par l'utilisateur (dépendance externe, non bloquante pour la rédaction du PRD).
- (decision) Affichage in-app de la fiche (renderSheet, hors export) = reproduction visuelle de la fiche papier dans l'idéal ; travail UX dédié nécessaire pour l'adaptation mobile (renvoyé à un futur run bmad-ux).
- (decision) Parcours de création de personnage = suit l'ordre des étapes extraites du guide (classe -> type -> attributs -> arme favorite -> objet fétiche -> équipement pique-nique -> champs narratifs), déclenché depuis la page détail de la partie (cohérent avec le point d'entrée 'Trouver une date' des Epics 2-3).

- (decision) Pivot de scope : PRD portera sur l'infra e-mail (SMTP) + notifications (sous-partie du Palier 4 backlog), pas l'évolution du personnage (Palier 3). Exigence explicite : prévoir un mode simulation/mock d'envoi de mail pour le dev/test local.
- (decision) Scope confirmé : les 3 cas d'usage (invitations par mail, rappels de séance, mot de passe oublié) sont dans ce PRD, pas de découpage ultérieur.
- (decision) Dev/test : serveur SMTP factice Mailhog (conteneur docker-compose, UI web + API HTTP :8025/api pour assertions e2e), pas de mode log-only.
- (decision) Prod : fournisseur SMTP recommandé Brevo (palier gratuit généreux, société française/RGPD, relais SMTP standard permettant swap dev->prod sans changement de code) — à confirmer par l'utilisateur.
- (event) Premier brouillon complet du PRD rédigé (Fast path) : infra e-mail (Mailhog dev/Brevo prod), invitation par e-mail, rappel de séance, mot de passe oublié. 4 assumptions taguées, 4 open questions.
- (decision) Fournisseur SMTP prod confirmé par l'utilisateur : Brevo.
- (decision) Gabarit d'e-mail : neutre unique, indépendant du thème visuel actif — confirmé par l'utilisateur.
- (decision) Délai rappel séance : 24h fixe en v1, confirmé. Déféré (noté pour PM) : rendre le délai configurable, et permettre au MJ d'envoyer un mail/notif ponctuel à la demande (hors rappel automatique).
- (decision) Durée de vie du lien de réinitialisation de mot de passe : 24h — confirmé par l'utilisateur (contexte hobby, tolérance préférée à la rigueur stricte).
- (decision) Pas de préférences de notification par utilisateur en v1 — confirmé par l'utilisateur.
- (decision) Log minimal (logs applicatifs existants, pas de dashboard) en cas d'échec d'envoi d'e-mail — confirmé par l'utilisateur. Toutes les assumptions/questions ouvertes de la revue sont désormais tranchées.
- (event) PRD mis à jour suite à la revue des assumptions/questions : toutes tranchées, aucune assumption ni question ouverte restante.

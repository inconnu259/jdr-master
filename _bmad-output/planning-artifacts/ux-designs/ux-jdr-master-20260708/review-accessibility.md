# Accessibility Review — jdr-master (Palier 3 delta)

## Overall verdict
The delta explicitly restates the inherited floor and does a genuinely good job on several fronts (private/shared note icon+text+aria-label, EncumbranceBar numeric value always shown, invitation-revoked-by-removal instead of greyed-out). But several *new* interactive components fall under the inherited touch-target floor without the "visual size vs. hit-area" exception the doc itself models for `FieldEditPencil`, one load-bearing visual distinction (MJ indicator) is color-only, a new badge text/background combination is contrast-borderline-to-failing on at least one theme, and aria-label coverage in EXPERIENCE.md §7 is incomplete relative to the new components introduced in DESIGN.md §7 (RosterStrip, invite-slot, stepper buttons, attribute-choice-grid). None of this is catastrophic — the pattern language is right, the coverage is just partial — but it needs another pass before this delta can be called floor-compliant.

## Findings

- **critical** `pv-pe-stepper` +/- buttons are specified (and rendered in the mock) at **28px**, used in a flow explicitly performed on mobile in the doc's own key flow (UJ-2, Alice on her phone) — well under both the 44px mobile floor and the 36px desktop floor, with no hit-area exception noted anywhere in DESIGN.md §7 or EXPERIENCE.md §6/§7. Unlike `FieldEditPencil`, this is not framed as a secondary/dense action — it's the primary control of the level-up wizard's PV/PE step. (location: DESIGN.md §7 `LevelUpWizard.pv-pe-stepper`; mock `.working/key-flows-xp-levelup-inventory.html` `.split-btn` = 28×28px). *Fix:* keep the 28px visual glyph if desired but state an explicit min hit-area (e.g. "28px visuel, 44px zone tactile mobile / 36px desktop"), same pattern as recommended for FieldEditPencil.

- **high** `RosterStrip` (mobile, MJ-only) items are specified at **26px avatar** / **32px invite-pill**, both under the 44px mobile floor, with no acknowledgment or hit-area note in DESIGN.md §7 or EXPERIENCE.md §7 — contrast this with the desktop `RosterRail` avatar-item (38px), which at least gets an inline comment about being a secondary nav element. RosterStrip items are full navigation entries (tap → character sheet) on mobile, where the floor is strictest. (location: DESIGN.md §7 `RosterStrip.item.avatar-size` / `RosterStrip.invite-pill`; mock `.working/layout-alternatives-mobile.html` `.strip-avatar` 26px, `.strip-add` 32px). *Fix:* either state an explicit larger tap-target padding around each pill/avatar, or document the exception explicitly the way avatar-item's comment does.

- **high** MJ indicator on `RosterRail`/`RosterStrip` avatars is **color-only**: `box-shadow: 0 0 0 2px {colors.accent-2}` with no accompanying icon or text badge in the visual design. This directly contradicts the inherited "couleur jamais seul vecteur d'information" floor for sighted users (screen-reader users are covered separately by the aria-label, but that doesn't fix the visual channel). It's also load-bearing: distinguishing the MJ from players in a shared roster is exactly the kind of state the floor rule exists to protect. Confirmed in the mock (`.rail-avatar.mj { box-shadow: 0 0 0 2px #9b6dff; }`, no icon/text). (location: DESIGN.md §7 `RosterRail.avatar-item.mj-indicator`; EXPERIENCE.md §7 aria-label note for RosterRail only covers the collapsed name/level pattern, not an "MJ" distinction). *Fix:* add a small icon (crown/star) or a "MJ" text chip on the avatar, in addition to the ring, and extend the aria-label pattern to explicitly say "MJ" instead of "niveau [N]" for that participant.

- **medium** Badge "ajouté par le MJ" contrast is borderline-to-failing depending on theme. It reuses the `rgba(accent-2, 0.12)` background + solid `accent-2` text pattern, at a very small font size in the mock (9px, `.item-source`). Rough eyeball WCAG estimate: Grimoire Émeraude (accent-2 `#9b6dff` on its own 12%-tinted `#1a1428` surface) comes out around ~4.4:1 — just under the 4.5:1 required for non-large text. Médiéval Steampunk (accent-2 `#4a7c59`, a muted bronze-green, on its 12%-tinted `#241808` surface) comes out closer to ~3.2:1, clearly under threshold. (location: DESIGN.md §2 "Badge ajouté par le MJ"; DESIGN.md §7 `InventoryItemRow.source-badge`; mock `.item-source` font-size 9px). *Fix:* verify with an actual contrast checker per theme; if steampunk/grimoire fail, either lighten the badge text color for those themes or increase font size to meet the "large text" 3:1 exception (≥18px / ≥14px bold), or add a subtle outline/weight bump.

- **medium** `attribute-choice-grid` cells and the `share-toggle` control have no stated pixel size in DESIGN.md §7, so their touch-target compliance can't be verified. This differs from other new components (avatar-item, pv-pe-stepper, FieldEditPencil, LevelUpBanner CTA) which at least state a size, even where that size is too small. (location: DESIGN.md §7 `LevelUpWizard.attribute-choice-grid`, `NotesJournal.entry.share-toggle`). *Fix:* state explicit cell/control dimensions (or min-height) so compliance can be checked, especially since attribute-choice-grid is used on mobile per UJ-2.

- **medium** `LevelUpBanner` CTA is specified only as "compact (padding 8px 16px)" with no explicit min-height, and is a primary action reached from mobile (UJ-2, Alice taps "Level up!" on her phone). 8px vertical padding plus a typical small-CTA line-height likely lands around ~36-40px total height — short of the 44px mobile floor — but this can't be confirmed without a stated size. (location: DESIGN.md §7 `LevelUpBanner.cta`). *Fix:* state an explicit min-height (e.g. `min-height: 44px` on mobile) rather than relying on padding + implicit line-height.

- **medium** aria-label coverage gap for several new interactive elements that have no corresponding note in EXPERIENCE.md §7, despite being introduced as distinct components in DESIGN.md §7: `RosterStrip` items/invite-pill (only `RosterRail`'s collapsed-avatar pattern is covered, not the mobile strip equivalent, which has the same "icon-only, name not visible" problem); the invite-slot "+" affordance (icon-only, no stated aria-label like "Inviter un participant"); the `pv-pe-stepper` +/- buttons (icon-only round buttons with no stated aria-label, e.g. "Diminuer PV" / "Augmenter PV"); `attribute-choice-grid` cells (no aria-label extending the inherited `"[Nom] : [état]"` pattern to selected/disabled attribute state). (location: EXPERIENCE.md §7, compare against DESIGN.md §7 component list). *Fix:* add one aria-label line per missing component, following the existing pattern already used for FieldEditPencil/LevelUpBanner/EncumbranceBar/notes.

- **low** EncumbranceBar's over-limit state is communicated by (a) a color-shifted gradient fill and (b) the same "[poids] / [limite]" numeric label used in the normal state — there's no explicit text/icon flag (e.g. "Surchargé" or a warning glyph) marking the over-limit condition itself; a user has to mentally compare the two numbers to notice they've crossed the line, with the color change as the main immediate signal. Technically this doesn't violate "color never the sole vector" (the numbers are present per EXPERIENCE.md §7), but it's a weaker signal than the rest of the delta's pattern (e.g. the badge, the lock icon) which pair state changes with explicit text. (location: DESIGN.md §7 `EncumbranceBar.fill-over-limit`; EXPERIENCE.md §7 EncumbranceBar note). *Fix:* consider an explicit inline label/icon when over limit (e.g. small warning glyph next to the numeric label), not just relying on the gradient + number comparison.

- **low** `attribute-choice-grid` disabled state (opacity 0.35, "attribut à 12") has no stated reason/tooltip text — a user sees a dimmed cell but no explanation of why (e.g. "Déjà au maximum (12)"). Likely mitigated by native `disabled`/`aria-disabled` semantics being assumed, but that's not stated explicitly. (location: DESIGN.md §7 `LevelUpWizard.attribute-choice-grid.states.disabled`). *Fix:* state the aria-disabled + reason text explicitly, e.g. via `title`/aria-describedby.

- **low** No reduced-motion consideration for the new `RosterRail` width transition (`transition: width {motion.duration.short} ease`). This is not a regression specific to this delta — neither `ux-jdr-master-20260626/EXPERIENCE.md` §7 nor `ux-jdr-master-20260703/EXPERIENCE.md` §7 defines a `prefers-reduced-motion` rule at all, despite both already using slide/transform transitions (BottomSheet, SidePanel). This delta simply inherits that pre-existing gap rather than introducing a new one, but since it adds another animated transition it's a reasonable point to flag upward. (location: DESIGN.md §4 RosterRail transition; EXPERIENCE.md §6). *Fix:* out of scope for this delta alone, but worth raising as a base-spine gap: add a `prefers-reduced-motion: reduce` rule to the inherited Accessibility Floor (§7) that all durations/transitions must respect.

- **low** The `RosterRail` avatar-item's inline comment (`# < 44px : élément de navigation secondaire, pas un CTA principal`) references the *mobile* 44px threshold to justify a component that is actually desktop-only (RosterRail doesn't exist on mobile — RosterStrip does) and where the relevant floor is 36px desktop, which 38px does satisfy. The justification is confusingly worded even though the actual value is compliant. (location: DESIGN.md §7 `RosterRail.avatar-item.size` comment). *Fix:* reword the comment to reference the correct 36px desktop floor it's actually satisfying, to avoid the reader wrongly concluding this is a knowingly-under-floor exception.

## What's solid

- Note privacy state (`NotesJournal.share-toggle`) is a model example: distinct icon shape (closed/open lock) *and* color *and* explicit aria-label text ("Entrée privée" / "Entrée partagée avec le groupe") — exactly what the inherited "color never alone" rule asks for.
- Invitation-revoked handling (link disappears entirely rather than being greyed out/struck through) is a deliberately accessible choice that avoids relying on a visual "disabled" treatment altogether, and is called out explicitly to prevent accidental clicks.
- `FieldEditPencil` sets a good precedent by naming its own touch-target shortfall ("secondary action, not primary CTA") and pairing the icon with an explicit `aria-label="Modifier [nom du champ]"` — the review's main critique is that this same discipline (explicit size/aria-label justification) wasn't consistently extended to the newer stepper, RosterStrip, and grid components.
- `LevelUpBanner`'s persistence + `aria-live="polite"` + "never a forced modal" combination is a thoughtful, non-disruptive notification pattern that respects both a player who's mid-task and one who's using a screen reader.
